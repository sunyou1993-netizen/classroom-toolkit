# 검사 도구

무언가를 고친 뒤에 **이 한 줄**만 돌리면 됩니다. 저장소 맨 위 폴더에서:

```bash
bash test/run.sh
```

마지막에 `✓ 모두 통과했습니다` 가 나오면 됩니다.
`✗` 가 있으면 그 줄에 무엇이 잘못됐고 어떻게 고치는지 적혀 있습니다.

---

## 무엇을 검사하나

| | 검사 | 무엇을 잡나 | 브라우저 |
|---|---|---|---|
| 1 | 문항 데이터 | 원본(JSON)과 화면에 나가는 것이 **문항 하나하나** 같은가. 정답이 하나라도 뒤집히면 아이들이 반대로 배웁니다 | 필요 없음 |
| 2 | 한자 글꼴 | 사자성어 한자가 글꼴에 다 들어 있는가. 빠지면 보드에서 네모(□)로 나옵니다 | 필요 없음 |
| 3 | 속담·사자성어 | 빈칸 글자가 실제 문장 안에 있는가, 중복이 없는가 | 필요 없음 |
| 4 | 교가·배포 준비 | 저장소에 **특정 학교 교가가 섞이지 않았는가**(저작권), 빌드 준비물이 다 있는가 | 필요 없음 |
| 5 | 사다리 공정성 | 참가자와 결과가 1:1 인가, 앞자리 아이가 뒤쪽 결과를 받을 수 있는가 | 필요 없음 |
| 6 | 화면 열어 보기 | 16개 화면이 오류 없이 열리는가, **바깥 인터넷으로 나가지 않는가**, 보드 해상도에서 꽉 차는가, 손가락으로 누를 수 있는 크기인가 | 필요 |
| 7 | 퀴즈 풀어 보기 | 실제로 풀어서 채점이 맞는가, 다 맞히면 100점인가, 연타해도 문제를 건너뛰지 않는가 | 필요 |
| 8 | 접근성 | 글자가 배경과 충분히 구분되는가(픽셀로 잼), 동작 줄이기를 존중하는가, 정답을 색 말고 글자로도 알려 주는가 | 필요 |
| 9 | 실행 파일 코드 | 교가.txt 를 읽는 부분이 이상한 입력에도 안 깨지는가 | `go` 필요 |

브라우저가 없으면 6·7·8 은 **건너뛰고** 준비하는 법을 알려 줍니다.
1~5 는 언제나 돌아가고, 이것만으로도 가장 위험한 것들(정답 뒤집힘, 한자 빠짐,
남의 학교 교가, 사다리 불공정)은 잡힙니다.

## 브라우저 검사까지 돌리려면

한 번만 준비하면 됩니다.

```bash
npm i -D playwright
npx playwright install chromium
```

이미 크롬이 깔려 있다면 그 경로를 알려 줘도 됩니다.

```bash
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" bash test/run.sh
```

## 이 검사들이 실제로 잡아낸 것들

만들면서 일부러 망가뜨려 보고, 다 잡히는지 확인했습니다.

| 망가뜨린 것 | 잡혔나 |
|---|---|
| 문항 하나의 정답을 O ↔ X 로 뒤집음 | ✓ `#1 ★정답 다름★ 원본 X / 번들 O` |
| 한자 글꼴에서 樂·雷·類 를 뺌 | ✓ `樂 U+6A02 (fourchar/…)` |
| 사다리 층 수를 옛날처럼 6개 고정으로 되돌림 | ✓ `12개 칸은 20000번 돌려도 한 번도 안 나왔습니다` |
| 저장소 번들에 특정 학교 교가를 넣음 | ✓ `지금 «서울신답초등학교» 입니다` |

## 검사가 다루지 **못하는** 것

솔직하게 적어 둡니다. 아래는 사람이 직접 확인해야 합니다.

- **진짜 AI보드에서의 동작** — 이 검사들은 컴퓨터의 브라우저로 흉내 낸 것입니다.
  터치 반응, 소리, 마이크, 전체화면은 실제 보드에서 한 번 봐야 합니다.
- **진짜 윈도우에서의 exe 실행** — SmartScreen 경고, 백신 오탐, 방화벽.
- **학교 인터넷에서 출처 주소가 열리는지** — `node scripts/check-sources.mjs`
  를 학교망에서 돌려 보세요.
- **문항 내용이 사실인가** — 검사는 "원본과 화면이 같은가"만 봅니다.
  원본 자체가 맞는지는 출처 문서를 사람이 읽어야 합니다.
- **화면이 예쁜가** — 색·배치·그림은 사람 눈으로 봐야 합니다.
